# pyOS — мини-ОС на Python (подобие Linux)

Учебный **симулятор операционной системы**, полностью написанный на Python.
Реализует виртуальную файловую систему, подсистему процессов с планировщиком,
пользователей с правами доступа, интерактивный шелл с пайпами и редиректами,
а также сетевые утилиты и пакетный менеджер. Ядро, ФС и процессы симулируются
внутри Python; сеть, снапшоты и очистка экрана при этом используют ресурсы хоста.

## Запуск

```bash
# из каталога D:\code
python -m pyos
```

При загрузке появится приглашение входа. По умолчанию пароли у учётных записей
пустые, поэтому достаточно ввести имя и нажать Enter:

| Логин  | uid  | Домашний каталог |
|--------|------|------------------|
| root   | 0    | /root            |
| user   | 1000 | /home/user       |
| guest  | 1001 | /home/guest      |

> **Неинтерактивный запуск.** В окружении без TTY (например, фоновый процесс
> с закрытым stdin) `login()` при EOF автоматически входит как `root`, а REPL
> завершается на первом же EOF. Для прогонов без терминала подавайте команды
> через stdin: первая строка — логин (`root`), затем команды, последняя —
> `exit`.

## Возможности

### Файловая система
- дерево узлов (файлы, каталоги, символические ссылки) в памяти;
- права доступа `rwx` для владельца/группы/остальных, как в POSIX
  (проверяется и право `x` на промежуточных каталогах);
- **жёсткие ссылки** (`ln` без `-s`): общий inode, данные и счётчик `nlink`;
- рекурсивное копирование `cp -r`;
- пути: абсолютные и относительные, `.`, `..`, `~`;
- `/tmp` с правами `1777`, `/root` закрыт (`700`);
- inode, размеры, время модификации, `stat`.

> Sticky-бит `/tmp` отображается в правах (`1777`), но POSIX-семантика
> защиты от удаления чужих файлов не реализована: `rm` в `/tmp` проверяет
> только права на сам каталог.

### Устройства, /proc и dmesg
- `/dev/null` (`666`), `/dev/zero` (`666`), `/dev/random` (`666`),
  `/dev/full` (запись завершается с `No space left on device`);
- динамические файлы `/proc/meminfo`, `/proc/uptime`, `/proc/cpuinfo`,
  `/proc/version`, статусы `/proc/<pid>/status` и `/proc/self/status`;
  каталоги pid пересобираются по живой таблице процессов;
- `dmesg` — кольцевой буфер сообщений ядра (загрузка, сигналы и т.п.).

### Процессы и планировщик
- таблица процессов с PID, PPID, владельцем, состоянием (N/R/S/Z/T);
- планировщик с квантами и симулированным временем (тики), учитывающий
  **приоритет `nice`** (взвешенное распределение CPU — чем меньше `nice`,
  тем больше процесс получает времени);
- состояния `READY`/`RUNNING`/`BLOCKED`/`TERMINATED`;
- фоновые задания (`&`), `jobs`, `fg`, `bg`;
- `sleep` блокирует процесс на заданное число тиков;
- `kill [-N] pid ...` посылает числовой сигнал (по умолчанию `15`, `-9` —
  принудительное завершение); имена сигналов хранятся в `pyos/signals.py`.

### Шелл и переменные
- конвейеры `|`, редиректы `>`, `>>`, `<`;
- фоновые задания `&` и разделитель `;`;
- логические операторы `&&` и `||` (`a && b` — `b` при успехе `a`,
  `a || b` — `b` при ошибке `a`);
- кавычки, экранирование (в одинарных кавычках и после `\` переменные
  не раскрываются);
- раскрытие `$VAR` / `${VAR}` и bash-операторы: `${VAR:-word}` (значение по
  умолчанию), `${VAR:=word}` (присвоить по умолчанию), `${VAR:+word}`
  (альтернатива), `${VAR:?word}` (ошибка, если переменная не задана или пуста);
- специальные переменные `$?` (код возврата) и `$$` (PID, под которым
  выступает оболочка; в текущей реализации это PID `init`, то есть 1);
- **локальные переменные** `VAR=value`, `export`, `unset`, `set`
  (префикс `VAR=value команда` передаёт переменную только команде);
- подстановка шаблонов `*`, `?`, `[...]` в незакавыченных аргументах;
- история, алиасы `alias`/`unalias`;
- `su` и `sudo` (смена пользователя, запуск от root);
- `nice -n N команда` — запуск с заданным приоритетом;
- `ulimit -f [блоки]` — лимит размера файла (в 1K-блоках), применяется
  при записи через редиректы; `unlimited` снимает лимит.

### Сеть
- `curl` и `wget` выполняют **реальные** HTTP/HTTPS-запросы через
  `urllib.request` (используется сеть хоста, поэтому нужен доступ в интернет);
- `curl -v` — вывод заголовков, `-o файл` — сохранить в виртуальную ФС,
  `-L` — следовать редиректам (по умолчанию не следует);
- `wget [-O файл] [-q]` — скачивание в виртуальную ФС, редиректам следует
  по умолчанию; имя файла берётся из URL;
- тело ответа декодируется как текст (кодировка из `Content-Type` или
  определяется по содержимому).

### Пакетный менеджер
- PKGBUILD-подход (как в Arch): переменные `pkgname`, `pkgver`, `pkgrel`,
  `pkgdesc`, `arch`, `depends` и функции `build()` / `package()`, которые
  выполняются командами шелла pyOS;
- `makepkg [PKGBUILD]` — сборка пакета в `/var/cache/packages`
  (только root; внутри шагов доступны `$srcdir` и `$pkgdir`);
- `pkg install|remove|list|info` — установка из кэша, манифесты хранятся
  в `/var/lib/packages` (управление — только root).

### Состояние и лимиты
- `save <файл>` — сохраняет ФС и пользователей в JSON **на реальном хосте**
  (аргумент — путь к файлу операционной системы, не виртуальной ФС);
- `load <файл>` — полностью заменяет текущее состояние ФС, пользователей
  и `hostname` из снапшота (только root);
- `ulimit -f` — см. раздел «Шелл и переменные».

## Команды

| Категория  | Команды |
|------------|---------|
| Файлы      | `ls`, `cd`, `pwd`, `cat`, `touch`, `mkdir`, `rmdir`, `rm`, `cp`, `mv`, `ln`, `chmod`, `chown`, `stat` |
| Процессы   | `ps`, `top`, `kill`, `sleep`, `uptime` |
| Текст      | `echo`, `grep`, `wc`, `head`, `tail`, `sort`, `uniq`, `rev`, `tr`, `cut` |
| Система    | `whoami`, `id`, `groups`, `uname`, `hostname`, `date`, `env`, `which`, `clear`, `df`, `free`, `dmesg`, `help`, `man`, `true`, `false` |
| Состояние  | `save`, `load`, `ulimit` |
| Сеть       | `curl`, `wget` |
| Пакеты     | `makepkg`, `pkg` |
| Встроенные | `cd`\*, `exit`, `export`, `unset`, `alias`, `unalias`, `history`, `jobs`, `fg`, `bg`, `nice`, `su`, `sudo`, `source`, `set` |

\* `cd` реализован и как обычная команда. `true`/`false` — команды, всегда
возвращающие код 0 и 1 соответственно; удобны в цепочках `&&`/`||`.

## Примеры

```bash
echo hello > /tmp/a.txt
cat /tmp/a.txt | grep hello
ls -lh /tmp
mkdir -p /tmp/dir/sub; ls -l /tmp/dir
sort -u /tmp/list.txt | head -n 3
cp -r /tmp/dir /tmp/dir-copy
echo "$HOME" > /tmp/n.txt; echo '$HOME' >> /tmp/n.txt   # только первый раскроется
ls /tmp/*.txt
ln /tmp/a.txt /tmp/a-hard.txt        # жёсткая ссылка
sleep 2 &
nice -n 5 sleep 3 &                  # фоновое задание с приоритетом
jobs
ps aux
sudo -u user whoami
chmod 600 /tmp/a.txt
ln -s /tmp/a.txt /tmp/link.txt
echo "hello" | tr a-z A-Z            # HELLO — диапазоны поддерживаются
echo a1b2c3 | tr 0-9 X               # aXbXcX, SET2 дополняется последним символом
NAME=Alice; echo ${NAME:-guest}      # локальная переменная + ${VAR:-word}
true && echo ok || echo fail         # true/false в цепочках
curl -o /tmp/page.html http://example.com    # реальная сеть хоста
wget -q http://example.com/
save pyos-snapshot.json              # снапшот на хосте, в текущем каталоге
load pyos-snapshot.json              # только root, состояние заменяется целиком
ulimit -f 4                          # лимит 4 КБ на запись через редиректы
```

## Тестирование

```bash
# из каталога D:\code
python -m pytest tests
```

- У проекта **нет** `pyproject.toml` / `pytest.ini`: пакет `pyos` становится
  импортируемым благодаря `tests/conftest.py`, который добавляет корень
  репозитория в `sys.path`.
- Фикстуры в `tests/conftest.py`: `kernel`, `root`, `user`, `shell`.
- Новые тесты добавляются как `tests/test_*.py`; интеграционные тесты идут
  через `Shell(...).handle_line(...)` + `capsys`.

## Архитектура

```
pyos/
  __init__.py       версия и имя ядра
  errors.py         исключения-аналоги errno
  users.py          пользователи, группы, пароли
  fs.py             виртуальная ФС (inode, права, symlinks, жёсткие ссылки)
  process.py        процесс и его состояния
  scheduler.py      планировщик с приоритетами (nice), тики
  signals.py        таблица сигналов (номера/имена, действия по умолчанию)
  kernel.py         ядро: связывает подсистемы, «системные вызовы», /proc и /dev
  context.py        контекст выполнения команды
  shell.py          токенизатор, парсер (пайпы/редиректы/фон), REPL, builtins
  main.py           загрузка, логин, запуск шелла
  __main__.py       запуск через `python -m pyos`
  commands/
    registry.py     реестр команд и метаданные для help/man
    fs_cmds.py      команды файловой системы
    process_cmds.py команды процессов
    text_cmds.py    текстовые утилиты (tr с диапазонами и экранированиями)
    system_cmds.py  системные команды и справка (вкл. true/false)
    network_cmds.py curl/wget через urllib.request (реальная сеть хоста)
    package_cmds.py пакетный менеджер: makepkg, pkg
    memory_cmds.py  save/load состояния ФС, ulimit
```

## Ограничения

- Это **симулятор**: процессы — объекты с тиками, а не реальные потоки ОС.
- Файловая система хранится только в памяти и теряется при выходе, если не
  сохранить её командой `save`.
- `save`/`load` работают с JSON-файлами на реальном хосте (не в виртуальной
  ФС); `load` полностью заменяет текущее состояние.
- Снапшот не сохраняет жёсткие ссылки, номера inode и времена файлов;
  после `load` жёсткие ссылки становятся независимыми файлами.
- `/proc` и `/dev` не сериализуются: после `load` они пересоздаются ядром
  как виртуальные узлы. Старые снапшоты, где они лежат обычными файлами,
  в этой части игнорируются.
- Sticky-бит `/tmp` (`1777`) отображается в правах, но защита от удаления
  чужих файлов не реализована.
- `kill` принимает только числовой номер сигнала (`-9`, `-15`); имена из
  `pyos/signals.py` (`kill -KILL`) не разбираются.
- Фоновые задания выполняются отложенно: `worker` завершает команду в момент
  выхода процесса и вручную двигает `scheduler.clock`. Связка хрупкая —
  менять её нужно вместе с тестами планировщика.
- `curl`/`wget` декодируют тело ответа как текст — бинарное содержимое
  может искажаться.
- `ulimit -f` ограничивает только запись через редиректы `>`/`>>`;
  `cp`, `wget`, `pkg` и `save` этот лимит не соблюдают.
- `fg` только дожидается завершения задания, `bg` лишь печатает его —
  полноценного управления заданиями нет.
- `sudo` не запрашивает пароль и не проверяет sudoers — любой пользователь
  может запустить команду от root.
- `pkg install` выбирает версию «последней по алфавиту», поэтому `1.10`
  может оказаться раньше `1.9`.
- `clear` очищает реальный терминал хоста, а не виртуальный экран.
- Пароли хранятся как SHA-256 без «соли»; это учебный код, не для продакшена.
- `df`/`free` показывают условные значения.
